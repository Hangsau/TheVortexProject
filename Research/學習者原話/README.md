# 學習者原話 → L 級／三型 對照研究

> 狀態：蒐集中（2026-10-14 開始）。研究底稿，**不進 canonical、不公開**（不在 my-site 研究筆記白名單）。
> 成果經使用者審過後，才挑選補進 `canonical/technica/water-sense-levels.yaml` 的 `diagnostic`（只進診斷層，E010）。

## 為什麼做

`water-sense-levels.yaml` 的 `diagnostic.type_states.*.typical_speech` 與判型題 Q1–Q3 全是教練撰寫，沒有實測語料。
論壇上學習者用自己的話描述卡關（「戴浮板就快 25 秒」「累的是手臂不是背」），量大且高度重複。
只取**問題**、不取回答：回答多半是通用口訣，無判讀價值。

**使用情境**：教練聽到學生說某句話 → 查這句話可能對應哪個 L 級、哪一型（或是硬體邊界／非感知問題）→ 用一個區辨問題把候選縮到一個。

## 抽句與對應規格（步驟 3）

**判準唯一來源是 `framework_card.md`**，不用分類者自己對 L 級的理解。

每篇貼文：
1. **是否收**：發文者以第一人稱描述**自己**游泳時的困難或感覺。器材選購、比賽資訊、純問配速／課表、替別人問、只有回答 → 不收。
2. **抽句**：一篇可抽多個單位；`speech_zh` 用中文改寫，**保留泳者自己的感覺用語**（「腳很沉」「像在爬坡」），不翻成專業術語、不加判讀。附 `quote_orig`（原文一句以內，供核對）。
3. **情境標記**：泳式、速度（慢／加速／衝刺）、距離或疲勞、器材（浮板、蛙鞋、划手板…）、換氣相關、被看／計時、自述背景（年齡層、成人初學／回鍋／競技／鐵人、泳齡）。
4. **對應**（可多候選，不硬塞單一）：
   - `level_candidates`：L0–L6（三型從 L3 才適用）。
   - `type_candidates`：A／B／C／none，各附一句理由，理由必須指向框架卡的具體條目 ID。
   - `non_perception`：hardware（踝／肩／髖活動度、體型浮力）、fitness、fear_panic、pacing、equipment、pain_injury、other。硬體邊界依框架卡「前置判斷」：泳者能描述**為什麼**做不到 → 硬體；不能描述或描述與結果矛盾 → 感知。
   - `discriminator`：多候選時，寫一個能把候選分開的問題（比照判型題 Q1–Q3 的形式）。
   - `matches`：若與既有 `typical_speech`／判型題選項說的是同一件事，填該條目 ID。
   - `certainty`：一律 🔴（自述≠實際狀態，未經觀察）。

## 已知偏壓（寫進報告，不是受眾界定）

- Reddit 偏成人初學、回鍋者、鐵人三項；兒童與競技選手幾乎不在論壇發文。
- PTT 偏台灣成人；早期文章年代久遠，泳技觀念可能過時（只取描述，不取觀念）。
- 依專案規則，這是**素材缺口**，不得據此把框架窄化到成人族群。
