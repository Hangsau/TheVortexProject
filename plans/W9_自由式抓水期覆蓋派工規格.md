## 這一層在做什麼（寫任何一個字之前先讀完）

動作圖譜是**列舉式**的：列出「這個相位牽涉到什麼關節動作、可能有哪些狀況」，
**不判定誰主導、不判定某個泳者被什麼限制、不規定要練到幾度**。

因此以下句型一律不得出現，出現即退件：

- 「主要由 X 肌群驅動」「X 是主動肌」「X 出力最多」——沒有相位化肌電振幅資料
- 「找出限制你的那塊肌肉」「先練 X 再練 Y」——這是處方
- 「應達到 N 度」「至少要 N 度才能抓到水」——這是門檻
- 「抓水做得好推進力比較大」「手掌面積越大推進越多」「指間紊流放大有效面積」
  ——**推進與流體宣稱本輪一律不寫**。庫裡確實有這類記錄
  （`free.tech.28` 的指間紊流、`free.tech.9` 的推進面積），但它們的證據是
  流體力學推導與游泳實測，不是本輪的解剖來源；把它們搬進 movement 層
  等於跨層借證。

### 數字紀律（W019 會擋）

`public.description` 等敘述文字裡**不得出現 `°`、`%`、`s`、`r=`**。
教科書的角度值與 `free.tech.28` 的毫米間距值**一律不寫進敘述**，改寫成
定性說法（「可用範圍在解剖上餘裕充足」「兩側旋轉都有可用範圍」）。
本輪**不使用** `measurement_conditions` 欄位。

### 兩欄鐵律（BK-30 已定案，本輪沿用）

**池畔可見方向**與**解剖學動作**是兩個欄位，不是同一件事。
`poolside_direction` 寫池畔看到什麼，`action_ids` 與敘述寫解剖學怎麼命名。
自由式是俯臥（`body_position: prone`），空間「向前」與解剖位的前方同向，
**不發生仰式那種矢狀面命名反轉**。但本輪的兩個可見現象都不能直接反推關節動作：

1. **「手臂由前伸轉為向外分開」不是關節角度從屈曲變成外展**（D1）。
2. **「掌心朝後下方」不能反推前臂旋前**（D2）。

## 前置裁決：本輪可用的三條（執行者不得更動、不得增補）

自由式登錄的分期是多套並存的，但 `catch` 這一個相位鍵登錄為 `descriptive`。
本輪只寫 `catch` 一個相位，因此 `phase_model` 固定 `descriptive`，不涉及跨模型問題。

| 裁決編號 | 裁決 | 衝突型 | 本輪用途 |
|---|---|---|---|
| FR-11 抓水期：肩由屈曲轉為輕度外展 ＋ 開始內旋 | **修正** | 型1（座標系衝突） | D1 主體 |
| FR-12 抓水期：肘開始屈曲（高肘抓水 EVF） | **部分支持** | 型4（跨層對撞） | D1 附帶（只取「肘屈曲」四字） |
| FR-14 抓水期：前臂旋前（手掌朝後下方） | **修正** | 型1（座標系衝突） | D2 主體 |

三條的裁決原文摘要（執行者據此寫，不得超出）：

**FR-11**：Neumann 明說「把手臂舉過頭在接近矢狀面時被非正式地稱為屈曲、
在接近額狀面或肩胛面時被稱為外展」，且他自己標注這是 informal 用法。
因此「由屈曲轉為外展」**不是關節角度改變**，而是**上舉所處平面移動**——
由矢狀面移向肩胛平面／額狀面。若手臂已在接近上舉一半的位置，該平面內的
移動應改稱**水平外展／水平內收**（Neumann：水平內收與水平外展的起始位置
定義在上舉一半處）。「開始內旋」這半句的命名本身成立。
**根因是結構性缺陷**：原表用「屈曲／外展」單一欄位承載三維動作，
缺少「上舉平面（plane of elevation）」欄位；只要相位跨越平面，
同一缺陷就會重複發生。

**FR-12**：「肘開始屈曲」命名成立，Neumann 把肘屈曲與 pulling 直接連結。
但括號的「高肘抓水（EVF）」是游泳專屬技術構念——它同時包含前臂朝向、
肘相對手的高度、以及推進假設，**超出解剖教科書可裁決範圍**；教科書既不能
支持也不能否定 EVF。此條可用的部分只有「肘屈曲」四個字。

**FR-14**：括號「手掌朝後下方」被當成「前臂旋前」的證據，這個推論在解剖學上
**無效**。手掌在空間中的朝向是**肱骨軸向旋轉 ＋ 前臂旋前旋後 ＋ 腕關節位置**
三者的合成；Neumann 明白寫出「當手固定時，這些旋前與旋後的運動學本質上是
盂肱關節主動外旋與內旋的表現」，也就是同一個手掌朝向可以完全由肩關節旋轉
達成，不需要前臂動。正確寫法是拆成兩欄：**手掌空間朝向**（可觀察）與
**前臂關節位置**（旋前／中立／旋後，需另行判定）。原主張「前臂旋前」
**未必錯**，但目前的依據不成立——這個分寸要寫準：本層不宣告它錯，
本層宣告的是「由掌心朝向推不出它」。

### 負面清單（本輪絕對不得產出的內容）

1. **不得寫「高肘」或「EVF」的任何實質內容**。可用的只有「肘屈曲」三個字。
   敘述裡可以說「教材另有『高肘抓水』與 EVF 等詞，涉及前臂朝向與推進假設，
   不在本層裁決範圍」，但不得描述其做法、好處、判準或失敗樣態。
2. **不得寫指間間距、紊流、有效面積的任何內容**。`free.tech.28` 只作為
   `derived_from_ids` 的來源條目引用，其流體主張不進本層。
   D2 可以說「教材另有描述抓水期的手部與手指配置，涉及流體假設，不在本層」，
   但不得複述其內容或數值。
3. **不得宣告「前臂旋前是錯的」**。FR-14 的裁決是「依據不成立」，不是
   「主張為假」。寫成「教材寫錯了」就是任務失敗。
4. **不得把「上舉平面移動」寫成一個新的關節動作名**。它是描述欄位的缺口，
   不是可命名的關節動作；`action_ids` 用既有的上舉、水平外展、水平內收等
   來承載，敘述裡明寫缺的是欄位不是動作。
5. **不得寫任何傷害宣稱**（肩夾擠、肩袖撕裂、肘內側疼痛等）。
   `safety_note` 只寫「出現疼痛、卡住、麻木、明顯無力或不穩應停止」這類
   通用停止條件，不得指名任何診斷。
6. **不得跨泳式比較**，不得寫「自由式的抓水比蝶式如何如何」。

### D1 上舉平面移動

- `id`: `movement.demand.free.catch.elevation-plane-shift-with-rotation-onset`
- `claim_status`: `partially-supported`
- `poolside_direction`：由池畔觀察，前伸的手臂開始向外側分開並轉向下方，
  肘出現屈曲（教學語稱「抓水」）
- `action_ids`（順序照抄）：
  ```yaml
    action_ids:
      - movement.action.shoulder-complex.elevation
      - movement.action.shoulder-complex.horizontal-abduction
      - movement.action.shoulder-complex.internal-rotation
      - movement.action.elbow.flexion
  ```
- `muscle_roles`（三筆，順序照抄）：
  `movement.muscle.scapular-upward-rotators`、`movement.muscle.rotator-cuff`、
  `movement.muscle.elbow-flexors`
- `public.name_zh`：自由式抓水期的上舉平面移動與旋轉起始
- `public.description` 必須依序寫到這四件事：
  1. **「由屈曲轉為外展」不是關節角度改變**。解剖來源明說，把手臂舉過頭
     這個動作，在接近矢狀面時被非正式地稱為屈曲、在接近額狀面或肩胛面時
     被稱為外展——**是同一件事的兩個名字，差別在上舉所處的平面**，
     而且來源自己標注這是非正式用法。
  2. **正確的描述是上舉平面由矢狀面移向肩胛平面／額狀面**。
     若手臂已在接近上舉一半的高度，該平面內的向後移動應改稱**水平外展**
     （見本輪新增的 A1，其定義綁在「上舉一半」這個起始位置上）。
     `action_ids` 同時列上舉與水平外展，就是因為抓水期橫跨這個界線，
     哪一個名稱適用取決於當下的上舉高度——**本層列舉兩者，不裁定切換點**。
  3. **「開始內旋」這半句成立**，內旋是肱骨繞縱軸的動作，與上舉平面是
     互相獨立的兩個軸，可以同時發生。「肘開始屈曲」也成立。
  4. **根因是欄位缺口不是命名錯誤**：原表用「屈曲／外展」單一欄位承載一個
     三維動作，缺少獨立的「上舉平面」欄位。只要相位跨越平面，同一缺陷就會
     重複出現在其他相位上。治本方向是把上舉平面設為獨立欄位，
     **不是換一個更準的單字**。
- `public.limitation_context`：本筆只承載命名與欄位結構。
  不含推進歸屬，不含「高肘抓水／EVF」的任何內容（那涉及前臂朝向與推進假設，
  不在本層）；`derived_from_ids` 指向的兩條記錄描述同一相位，
  但其流體與推進主張不由本筆繼承。
- `public.safety_note`：通用停止條件，不指名任何診斷。
- `diagnostic.assessment_note`：評估時須把上舉高度、上舉平面、肱骨軸向旋轉
  三項分開記錄，不得由「手向外分開」單一觀察填任一欄。現有來源支持命名與
  一般解剖能力，沒有自由式專項的相位化運動學量測，因此不足以升為 ready，
  `action_status` 維持 provisional。

### D2 掌心朝向的三源分解 — **本輪最重要的一筆，請完整讀完再寫**

- `id`: `movement.demand.free.catch.palm-orientation-three-source-decomposition`
- `claim_status`: `partially-supported`
- `poolside_direction`：由池畔或水下窗觀察，抓水期的掌心轉為朝向後下方
  （教學語稱「前臂旋前」「立掌」）
- `action_ids`（順序照抄——**五筆一個都不能少，也不能多**）：
  ```yaml
    action_ids:
      - movement.action.shoulder-complex.internal-rotation
      - movement.action.forearm.pronation
      - movement.action.forearm.supination
      - movement.action.wrist-hand.flexion
      - movement.action.wrist-hand.extension
  ```
  （共五筆。**旋前與旋後兩個相反方向必須同時列**，腕屈與腕伸同理——
  理由見下方 description 第 3 點：本層列舉的是「掌心朝向這個觀察值可以由哪些
  關節位置組合出來」，不是「抓水期一定在旋前」。把旋後或腕伸刪掉、
  或改成只留單一方向，就是任務失敗。）
- `muscle_roles`（四筆，順序照抄）：
  `movement.muscle.shoulder-internal-rotator-extensors`、
  `movement.muscle.forearm-pronators`、`movement.muscle.forearm-supinators`、
  `movement.muscle.wrist-flexors`
- `public.name_zh`：掌心空間朝向與前臂關節位置是兩個欄位
- `public.description` 必須依序寫到這五件事：
  1. **「手掌朝後下方」不能當成「前臂旋前」的證據**。這是本筆的全部要點。
     教材把可觀察的掌心朝向寫在括號裡當作關節動作的依據，
     這個推論在解剖學上不成立。
  2. **掌心在空間中的朝向是三個獨立來源的合成**：肱骨繞縱軸的軸向旋轉、
     前臂的旋前旋後、腕關節的位置。三者各自都能改變掌心朝向，
     單看掌心無法分辨改變來自哪一個。
  3. **解剖來源直接示範過這件事**：當手被固定時，看起來像旋前旋後的運動學
     「本質上是盂肱關節主動外旋與內旋的表現」。也就是說，
     **同一個掌心朝向可以完全由肩關節旋轉達成，前臂完全不動**。
     這正是 `action_ids` 同時列旋前與旋後、同時列腕屈與腕伸的理由：
     本筆列舉的是能產生這個觀察值的關節位置組合，不是宣告抓水期處於哪一個。
  4. **本層不宣告「前臂旋前」為假**。原主張未必錯，本層宣告的是
     「由掌心朝向推不出它」。這兩件事的差別很重要：
     前者是否證，後者是依據不成立——寫成教材寫錯了就超出本層。
  5. **根因是欄位缺口**：原表缺「空間朝向 vs 關節位置」的分欄。
     治本方向是拆成兩欄——**手掌空間朝向**（可觀察，池畔就能記）與
     **前臂關節位置**（旋前／中立／旋後，需以前臂本身的參考標記或影像另行判定）。
     凡是以手掌朝向反推關節動作的地方都會複製同一個錯，
     不是只有抓水期這一處。
- `public.limitation_context`：本筆只處理「觀察值與關節欄位的對應關係」。
  不含推進歸屬、不含手部與手指配置的流體內容（那涉及流體假設，不在本層）、
  不含高肘與 EVF；`derived_from_ids` 指向的兩條記錄描述同一相位，
  但其流體與推進主張不由本筆繼承。**也不含「應該旋前多少」這種門檻**。
- `public.safety_note`：通用停止條件，不指名任何診斷；另加一句
  「不要為了做出特定的掌心朝向而勉強改變肩或前臂的旋轉位置」。
- `diagnostic.assessment_note`：評估時須直接量肱骨軸向旋轉與前臂旋轉兩項，
  並把掌心朝向另列為觀察值，不得由掌心朝向反推任一關節。現有來源支持
  三源分解與關節命名，沒有自由式抓水期的相位化旋轉量測，
  因此不足以升為 ready，`action_status` 維持 provisional。

## 六條硬規則（每一筆都要過）

1. **列舉不裁決**：不得寫「主導」「主要」「最重要」「最有效」；
   不得指名某一塊肌肉是限制來源；不得寫任何角度或次數門檻。
2. **不跨層借證**：本輪 `source_ids` 一律只有 `src.neumann-2017`。
   推進、流體、指間間距、EVF 的任何實質內容都不得出現在敘述裡。
3. **數字紀律**：敘述文字裡不得出現 `°`、`%`、`s`、`r=`；
   不使用 `measurement_conditions` 欄位。
4. **兩欄鐵律**：`poolside_direction` 只寫看到什麼，
   `action_ids` 與敘述寫解剖學怎麼命名；不得在 `poolside_direction` 裡
   寫關節動作名。
5. **D2 的五個 action 不得被「修正」掉**。旋前與旋後同時在場、
   腕屈與腕伸同時在場，是本筆的核心內容不是筆誤。
   刪成單一方向、或改寫成「抓水期應為旋前」，就是任務失敗。
   同理 D1 的上舉與水平外展並列也不得合併成一個。
6. **公開／診斷分層**：`public` 底下只能有本檔指定的鍵；
   任何判讀語、分型、探問句只能放 `diagnostic`（E010 是 ERROR 級）。
7. **最後跑 `python tools/validate.py`**，必須 0 ERROR，且 W013–W019 全部為 0。
   有任何一項不為 0 就自己修到 0，不要回報「還有幾個 warning」了事。
