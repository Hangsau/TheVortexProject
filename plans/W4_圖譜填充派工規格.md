## 資料模型速查

四個內容檔，四個命名空間，互不冒用：

| 檔案 | list 鍵 | ID 命名空間 | 內容 |
|---|---|---|---|
| `canonical/movement/actions.yaml` | `actions:` | `movement.action.*` | 關節／節段動作定義、平面與軸、可觀察邊界、一般解剖能力 |
| `canonical/movement/muscle-groups.yaml` | `muscle_groups:` | `movement.muscle.*` | 肌群名稱、跨關節特性、可承擔角色 |
| `canonical/movement/stroke-demands.yaml` | `demands:` | `movement.demand.*` | 泳式 × 相位 × 解剖動作 × 肌肉角色 |
| `canonical/movement/interventions.yaml` | `interventions:` | `movement.intervention.*` | 依限制型態的訓練與活動度決策 |

**每個檔案開頭的註解區塊就是該檔的完整欄位 schema**——動筆前逐行讀完，欄位名與順序照抄。
**既有記錄就是格式範本**：`actions.yaml` 已有 2 筆、`muscle-groups.yaml` 5 筆、
`stroke-demands.yaml` 3 筆、`interventions.yaml` 4 筆，新記錄的欄位順序、縮排、
`>` 摺疊字串風格一律比照。

### ID 規則

- 格式 `movement.<層>.<區或泳式>.<語意>`，小寫英文與連字號
- **ID 不含角度數字、證據等級或可變文案**——內容修正時不應被迫換 ID

### 四個狀態欄位（每筆記錄都必填，不可互相冒用）

| 欄位 | 取值 | 語意 |
|---|---|---|
| `publication_status` | `draft` / `reviewed` / `published` / `withheld` | 發布狀態。**本批一律 `draft`** |
| `claim_status` | `supported` / `partially-supported` / `disputed` / `unverified` | 主張的證據支持度 |
| `action_status` | `ready` / `provisional` / `do-not-prescribe` | 可否據以行動 |
| `evidence_profile` | `anatomy` / `swimming-kinematics` / `swimming-emg` / `intervention` / `practice-observation` / `synthesis-inference` | 證據性質 |

### public／diagnostic 分層（**E010 是 ERROR 級，不是警告**）

- `public`：正確命名、一般肌肉角色、教育性訓練選項、白話版適用與不適用條件、
  公開安全停止條件與來源。
- `diagnostic`：被動／主動 ROM 測量、力量耐力測試、如何分類限制、教練決策樹、
  個別水中重測判讀。
- **安全訊息一定要留在 public**：疼痛、急性傷、明顯不穩、麻木無力等「不要強拉」
  必須公開；具體診斷推理仍不公開。
- 洩漏的唯一實際路徑是**把診斷內容寫進 `public` 底下**。診斷判讀語
  （`perception_probe` / `signal_structure` / `discriminators` / `type_diagnosis` /
  `manipulation` / `contrast_question`…）只要出現在 `public` 子樹就是 ERROR。

## 八條跨區硬規則（每一筆都要過）

1. **零條原封不動通過**。C 類 39 條蒐證，四批全部沒有一條可以照抄原主張。
   本檔「可寫入」欄的文字才是依據，原主張句一律不得直接搬進 canonical。
2. **數值一律不進 demand 的需求語句**。角度、秒數、組數、百分比都不寫成需求；
   要交代數值時只能走 `measurement_conditions`（見下）。
3. **不得出現「沒有／零／不做」這種絕對運動學宣稱**。沒有人量到，不等於量到零。
4. **不得出現未附正負向與參考系的「同側／對側」**。
5. **`body line`／`racing streamline`／`hyperstreamline` 三個詞不得互換**，
   各自是不同的姿勢定義。
6. **凡引用相位，一律綁 `phase_model`**。跨模型的相位名不可互相換算，
   也不可並列比先後（BK-26 裁決）。
7. **`mobility_decision: evidence-gap` 必須同時配 `action_status: do-not-prescribe`
   與空的 `dosage_source_ids`**（W016 強制）。標了不知道就不得同時給出可照做的處方。
8. **傷害終點與效能終點分屬不同條目**，不得互相引用支撐。

### 相位鍵（W017 強制）

`(stroke, phase)` 組合必須登錄在 `canonical/_taxonomy.yaml#movement_phase_registry.strokes`，
且該筆的 `phase_model` 必須與登錄表對該 phase 的登錄**完全一致**。
**不得在 demand 端就地發明相位名。** 本區用到的組合已在下方參數表逐筆給出。

### `action_reference_frame`（W018 強制，本批新欄位）

宣告「本筆的 `action_ids` 是以哪個基準成立的」：

| 取值 | 語意 |
|---|---|
| `joint-local` | 宣稱近端節段相對的關節動作（肱骨相對肩胛、股骨相對骨盆）。**唯一可以寫關節角度需求的取值**，代價是 `source_ids` 不得為空（除非已標 `do-not-prescribe`） |
| `body-fixed` | 以泳者身體長軸與體平面為基準的節段朝向，隨滾轉一起轉 |
| `poolside-fixed` | 只以池畔固定座標描述的可見空間需求；採用它等於宣告**本筆不宣稱關節角度大小** |

`poolside_direction` 是輔助觀察欄，三種取值都可以並存帶它，它本身不宣告基準。

### `measurement_conditions`（W019 強制，本批新欄位）

**本筆文字只要出現百分比、角度、秒數或 `r=`／`d=`／`p=`，就必填。**
是 list，每個元素都是 dict，六個子鍵**全部必填且不得留空**：

```yaml
measurement_conditions:
  - source_id: src.xxx            # 必須能解析到 canonical/_sources.yaml
    quantity: 量的是什麼（含對照組是什麼）
    value: 含單位與區間，逐字照原文，不自行換算
    conditions: 手臂姿勢／速度／水深／被動或主動／族群與 n
    endpoint: passive-drag／swim-velocity／joint-angle／injury-incidence 擇一
    extrapolation_boundary: 這個數字不能外推到哪裡
```

原文沒給的子鍵，寫「原文未報告」，**不得留空、不得猜**。
