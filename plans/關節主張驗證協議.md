# 關節主張驗證協議

建立：2026-08-17
適用：以通用肌骨教科書驗證游泳關節動作描述的工作（首個對象＝`游泳四式關節動作全拆解(整合版)`）

---

## 0. 這份協議要解決什麼

把一份來源等級低的關節動作筆記，逐條裁決成可信內容。核心難點不是「查資料」，而是**遇到說法衝突時如何處理**——處理錯會把正確的內容一起殺掉。

## 1. 來源與其能回答的問題

| 來源 | 能裁決 | 不能裁決 |
|---|---|---|
| `src.neumann-2017`（Neumann 3rd ed） | 關節骨動學定義、ROM **正常上限**、肌肉作用線與力矩 | 游泳分期、推進機制、時序、**游泳實際用到幾度** |
| `src.nordin-frankel-2012`（Nordin & Frankel 4th ed） | 組織力學、各關節生物力學原理 | 同上 |
| `resources/books/Science_of_Swimming_Faster/`（234 檔） | 游泳專項關節角度、分期運動學、推進、肌力訓練姿勢 | 解剖動作命名 |
| `resources/books/Fundamentals_of_Fast_Swimming/`（34 檔） | 同上（Race Club，含儀器量測章節） | 同上 |
| `resources/books/swimming-kinetic-chain/` 游泳文獻集（43 篇） | 自由式／仰式／水下蝶腳的運動學與推進 | 解剖動作命名；**蛙式、蝶式、踝、body roll 皆 0 篇，不得用其「查無」下結論** |

**兩本肌骨教科書都不是游泳來源**（Nordin 全書 0 處提及 swimming，Neumann 僅 5 處）。它們提供的是**關節層裁決基準**，不是游泳知識。

### 1a. 角度數值的兩層區分（B 類必用）

一個角度主張要先問清楚它問的是哪一件事，兩者由不同來源裁決、互相不能否證：

| 層 | 問題 | 裁決者 |
|---|---|---|
| **解剖上限** | 這個關節最多能到幾度？ | Neumann（ROM 正常值） |
| **游泳實際值** | 游泳時實際上是幾度？ | 兩本游泳書（有量測就用）；查無則標「待游泳量測」 |

游泳書已確認含此層資料，例如 `Science_of_Swimming_Faster` Figure 2.7 給出**整個划手週期各時點的平均肘角度，並分 sprint 與 distance 兩種配速**（註明 180° 為肘完全伸展）。這類數值比 ROM 正常值有用得多，因為多數技術爭議問的是實際值不是上限。

**判定規則**：實際值落在解剖上限內 → 教科書不構成反證，不得標為衝突（見第 4 型）。只有實際值**超過**解剖上限，教科書才有否證權——那代表量測基準定義錯了或數字抄錯（見 `free.tech.39` body roll 45° 事件）。

### 1b. 傷害主張：文獻優先，無文獻時可推導但降級

傷害宣稱一律先找運動醫學文獻（NCBI E-utilities）。**確認無文獻時，允許改以關節力學推導**，但受以下限制：

- 推導出來的是**負荷描述**：「此位置使某結構承受某方向的張力／壓迫」。標 🔵。
- **不得推導出來的**：發生率、盛行率、風險倍數、「常見／好發」等頻率語言，以及具名診斷（「會造成 SLAP 損傷」）。這些只能來自文獻，沒有就是沒有。
- 推導必須寫出**依據的解剖事實與其出處**（Neumann／Nordin 的哪一段），不能只寫結論。
- 條目內必須明寫「此為解剖推導，尚無游泳專項文獻證實」，不得與有文獻支撐的傷害條目在呈現上混為一談。

理由：`plans/關節主張裁決_C類傷害宣稱.md` 已證實原始筆記的傷害宣稱 3/5 與文獻不符、其中 2 條方向相反——**傷害領域的「聽起來合理」特別不可靠**（原文寫「內旋內收致前脫位」，解剖上那是後脫位方向）。所以推導可以用來說明力學，不能用來冒充流行病學。

## 2. 主張三分類（裁決前必先分類）

| 類 | 內容 | 裁決者 |
|---|---|---|
| **A** | 解剖動作方向：屈/伸、內收/外展、內旋/外旋、肩胛骨動作命名 | 教科書，硬裁決 |
| **B** | 關節活動度數值 | 教科書給正常上限，只能判「解剖上是否可能」，答不了「游泳實際用多少」 |
| **C** | 游泳專屬時序與推進：分期命名、推進機制、打腿時機、划距效益 | 教科書**完全無法裁決**，須游泳文獻 |

最常見的誤判：把 C 類拿去問教科書，然後因為查不到而標成「未驗證」——那是分類錯誤，不是證據不足。

## 3. 衝突分型與解法

| 型 | 特徵 | 解法 |
|---|---|---|
| **1 座標系衝突** | 兩套術語系統沒對齊（池畔視角 vs 解剖視角） | 加欄位讓差異顯性化，**不選邊** |
| **2 內部自相矛盾** | 同一文件互斥 | **不投票、不取多數**；回第一性原理獨立推導後再比對兩方 |
| **3 簡化 vs 精確** | 粒度不同，兩者都不算錯 | **不判錯**；標「相位內有變化」，保留教學簡化版並註精確版 |
| **4 跨層對撞** | 教科書 vs 游泳文獻 | **不對撞**。教科書只能否證「解剖上不可能」，不能否證「游泳時不這樣做」 |
| **5 真實學界分歧** | 各方都有證據 | 保留爭議，列各方立場＋各自成立條件，不強行收斂 |

**最易犯錯**：把第 3、4 型誤判成第 2 型——把「粒度不同」與「回答不同問題」當矛盾去裁決，結果砍掉有用的內容。

## 4. 來源優先序（**僅在同型衝突內**適用）

1. 解剖學動作定義 — 不可協商，教科書裁決
2. 直接量測的游泳運動學研究
3. 教科書模型／正式教材
4. 教練慣例、商業教學網站 ← 待驗證筆記目前主要依賴此層

此階梯**不跨型使用**：第 4 型不得以「教科書層級較高」推翻游泳文獻，因兩者未回答同一問題。

## 5. 根因判定（每條衝突必答）

> 這是單點錯誤，還是缺欄位的症狀？

若同類錯誤會反覆發生 → 屬結構性缺陷，**治本是補欄位，不是修那一格**。

已知案例：「上踢/下踢」是池畔可見方向，「屈曲/伸展」是解剖動作，仰式使兩者翻轉 180°，而原文件無欄位承載此區別 → 錯誤必然發生。修正＝強制雙欄標注（池畔可見方向 ＋ 解剖學動作）。

## 6. 產物格式

每條衝突輸出一筆判定記錄，**不刪除錯誤版本**：

```
ID | 原文主張 | 類(A/B/C) | 衝突型(1-5) | 裁決(支持/修正/無法裁決) | 依據來源+定位 | 根因是否結構性
```

保留錯誤版本的理由：否則三個月後有人用同樣的商業網站再寫一次同樣的錯，沒有任何東西擋得住。

## 7. 驗收條件

- 每條主張有 verdict ＋ 來源定位（章節／頁碼）
- 懸空 `<cite index="...">` 標記全數清除（原文 12 處，無法解析）
- C 類明確標記「待游泳文獻」，不得偽裝成已驗證
- `python tools/validate.py` 0 ERROR
- 整合後依 `resources/CLAUDE.md` 規範刪除 `raw/notes/` 原檔
