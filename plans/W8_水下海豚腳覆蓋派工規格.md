## 這一層在做什麼（寫任何一個字之前先讀完）

動作圖譜是**列舉式**的：列出「這個相位牽涉到什麼關節動作、可能有哪些狀況」，
**不判定誰主導、不判定某個泳者被什麼限制、不規定要練到幾度**。

因此以下句型一律不得出現，出現即退件：

- 「主要由 X 肌群驅動」「X 是主動肌」「X 出力最多」——沒有相位化肌電資料
- 「找出限制你的那塊肌肉」「先練 X 再練 Y」——這是處方
- 「應達到 N 度」「至少要 N 度才能做出流線」——這是門檻
- 「研究顯示」——本輪的來源是解剖教科書，只能寫「解剖來源指出」
- **「流線做得好阻力比較小」「上踢是推進動作」「膝彎曲是主要正面阻力來源」**
  ——這一輪新增的禁句。這三句都是水動力學／推進宣稱，它們的出處是
  `udk.tech.10`、`udk.tech.15`、`udk.tech.24` 引的游泳文獻，**不是本輪的解剖
  來源**。本輪只寫關節命名與一般解剖可用能力，一個推進字都不准寫。

`evidence_profile` 全部是 `anatomy`，意思是：**這些來源只支持關節命名與一般
解剖可用能力，不支持任何水下海豚腳專項的運動學、時序或推進宣稱**。所有
`muscle_roles` 的 `role` 敘述都必須自己聲明這個邊界（照本檔給的樣板句寫）。

### 數字紀律（W019 會擋）

`public.description` 等敘述文字裡**不得出現 `°`、`%`、`s`、`r=`**。
教科書的角度值（伸展約 20 度、腰椎屈 45–55 度、蹠屈 40–55 度之類）
**一律不寫進敘述**，改寫成定性說法（「可用範圍明顯小於同一關節的反方向」
「不同量測方法得到的數值差異相當大」）。
本輪**不使用** `measurement_conditions` 欄位——因為這些數值是教科書的一般
解剖範圍，不是水下海豚腳的量測結果，硬塞六欄量測條件就是造假。

## 本輪的核心：體位翻轉（ST-13／ST-16 裁決，執行者不得更動）

**這是 W8 最重要的一段，讀不懂就不要開始寫。**

水下海豚腳有**兩種體位**，而且互為 180 度：

- **出發跳水後 / 自由式・蛙式・蝶式轉身後**：俯臥（腹側朝池底）。
- **仰式轉身後**：仰躺（腹側朝水面）。

骨動學命名鐵律：關節動作一律從**解剖位置**命名，**不隨身體在空間中的朝向改變**。
屈曲是大腿往腹側移動、伸展是往背側移動，跟「池畔看到腳往上還是往下」無關。

因此同一個池畔可見動作，在兩種體位下對應**相反的解剖動作名**：

| 體位 | 上踢（腳往水面） | 腹側朝向 | 解剖動作 |
|---|---|---|---|
| 俯臥 | 腳往水面 | 朝池底 | 腳往背側 → **髖伸展** |
| 仰躺 | 腳往水面 | 朝水面 | 腳往腹側 → **髖屈曲** |

**教材常見的寫法是「動作模式與蝶式的海豚打腿相同」，這句話把俯臥的命名直接
輸出到仰躺，而仰式選手每一次轉身後都在仰躺體位做水下海豚腳。** 本輪的 D5 與
D6 就是把這件事拆成兩筆記錄，一筆俯臥一筆仰躺。

**翻轉只發生在髖與軀幹，不發生在膝與踝**——這句必須明寫進 D5 與 D6，
否則讀者會以為要把整段打腿描述全部鏡像。理由：膝只有屈曲一個方向可用
（不存在以生理性過伸為主的動作），踝的蹠屈同理，所以它們的解剖命名在兩種
體位下不變，變的只是它們對應的池畔可見方向。**唯有在中立位兩側都有可用範圍
的關節（髖、脊椎）才會發生 180 度命名翻轉。**

### 兩欄鐵律

**池畔可見方向**與**解剖學動作**是兩個欄位，不是同一件事。
`poolside_direction` 寫池畔看到什麼，`action_ids` 與敘述寫解剖學怎麼命名。

## 負面清單（本輪絕對不得產出的內容）

1. **不得寫「流線型能減少阻力／迎水面積」的任何實質內容**。ST-12、ST-04 降級
   的唯一原因就是原文把水動力學結果寫進了解剖格。可用的只有關節命名。
   敘述裡可以說「教材另有『減少迎水面積』一類說法，該說法屬水動力學，
   不在本層裁決範圍」，但不得描述其機制、幅度或效益。
2. **不得把「肩胛上迴旋、後傾、上提」三者寫成同等必然**。ST-05／ST-06 明示
   上迴旋與後傾是手臂過頭的**必然伴隨成分**；ST-07 明示上提**不在**必然清單
   裡，只是「容許有一些」。三者並列而不區分必然性程度，正是 ST-07 降級的原因。
3. **不得由手掌的空間朝向反推前臂旋轉**。三種疊手法（掌根疊、手背疊、交握）
   對應**不同的前臂旋前旋後角度**，而手掌在空間中的朝向是肱骨軸向旋轉、
   前臂旋前旋後、腕位置三者的合成。這是 D2 的核心。
4. **不得把「脊椎中立或些微伸展（hollow body）」照抄成一個成立的主張**。
   這句話內含矛盾，見 D4 的完整說明。不得選邊，也不得把它寫成「教材寫錯了」
   ——正確處置是列出兩個讀法各自指向哪一側，並指出缺的是節段、平面、基準三欄。
5. **不得寫「膝彎曲過大要先排查踝關節」這類介入順序**。`udk.tech.15` 有這段
   實務建議，但那是處方，不進本層。本層只能寫「池畔看到的膝彎曲程度有一個
   以上的可能來源，外觀本身不能指定是哪一個」。
6. **不得寫任何傷害宣稱**（肩夾擠、頸部夾擠、腰椎壓力等）。ST-07 的「頸部
   夾擠」已在裁決檔判為 C 類未支持；夾擠在解剖來源裡的論述對象是**肩峰下
   空間**，不是頸部，兩者不得混用同一個詞。
7. **不得寫 `udk.down-kick`、`starts-turns.underwater-glide` 的新內容**
   ——這兩個相位已有 demand，本輪不動，也不得修改它們。

### A1 `movement.action.shoulder-complex.scapular-upward-rotation`

| 欄位 | 值 |
|---|---|
| `name` | 肩胛骨上迴旋 |
| `aliases` | `[肩胛上迴旋, 肩胛骨上旋, scapular upward rotation]` |
| `joint_region` | `shoulder-arm` |
| `plane` | `[frontal]` |
| `axis` | `[通過肩胛骨的前後軸]` |
| `claim_status` | `supported` |
| `action_status` | `ready` |
| `source_ids` | `[src.neumann-2017]` |

`definition`：肩胛骨相對胸廓的旋轉，關節窩轉向上方、下角轉離脊椎。它不是單一
關節的動作，而是**胸鎖關節的鎖骨上舉與肩鎖關節的肩胛上迴旋加總而成**的
肩胛胸廓合成動作——這一點必須寫，因為它決定了「上迴旋做不出來」時要往兩個
不同關節去看，不是一個。

`observable_boundaries` 必須寫兩點：
1. **這是手臂舉過頭的必要組成部分**，不是可有可無的附加動作。解剖來源直接
   把它定義為抬臂過頭的一部分，作用是讓關節窩得以支撐並穩定被舉起的肱骨頭。
   因此在雙臂夾耳的流線姿勢裡，上迴旋必然正在發生。
2. 肩胛骨**可以**嚴格在額狀面上迴旋，但多數情況沿其自身的肩胛骨平面行進。
   因此「上迴旋」與「上舉平面」是兩個要分開記錄的欄位。

### A2 `movement.action.shoulder-complex.scapular-posterior-tilt`

| 欄位 | 值 |
|---|---|
| `name` | 肩胛骨後傾 |
| `aliases` | `[肩胛後傾, posterior tilt, scapular posterior tilting]` |
| `joint_region` | `shoulder-arm` |
| `plane` | `[sagittal]` |
| `axis` | `[通過肩胛骨的內外側軸]` |
| `claim_status` | `supported` |
| `action_status` | `ready` |
| `source_ids` | `[src.neumann-2017]` |

`definition` 要寫齊兩件事，缺一不可：
1. **這個術語的定義層級是肩鎖關節**：矢狀面調整繞近內外側軸發生，外觀上是
   肩胛骨下角轉離胸廓後表面；**命名依據是關節窩的旋轉方向**，不是下角本身。
2. 但在描述姿勢時，讀者關心的是**肩胛骨相對胸廓**的最終位置，那是肩胛胸廓
   層級的合成結果。兩個層級都要標，否則與 A1（明確是胸鎖＋肩鎖加總）並列時，
   讀者會誤以為後傾與上迴旋發生在不同機制上。

`observable_boundaries`：解剖來源指出，上舉過程中上迴旋的肩胛骨**必然伴隨不等量
的後傾與淨外旋**，其作用包括讓肩胛骨貼合胸廓曲度、讓關節窩朝向手臂預定的上舉
平面、並讓喙肩弓遠離前進中的肱骨頭。所以後傾與 A5（肱骨外旋）**是同一個問題的
兩個對策**——一個轉肩胛、一個轉肱骨。這句要寫，它是 D1 的骨架。

`general_anatomical_capacity`：後傾的幅度隨上舉角度變化（「不等量」是原文用語），
本條不以單一角度作能力門檻。

| `action_status` | `ready` |

### D1 流線滑行：肩部的雙重避讓與肩胛三軸的必然性差異

```yaml
  - id: movement.demand.udk.streamlined-glide.scapulohumeral-dual-clearance
    phase: streamlined-glide
    body_position: prone
    poolside_direction: 由池畔觀察，推牆後雙臂夾耳伸直、雙手在頭前疊合，身體拉成一直線
    derived_from_ids:
      - udk.tech.24
    action_ids:
      - movement.action.shoulder-complex.elevation
      - movement.action.shoulder-complex.external-rotation
      - movement.action.shoulder-complex.scapular-upward-rotation
      - movement.action.shoulder-complex.scapular-posterior-tilt
      - movement.action.shoulder-complex.scapular-elevation
    claim_status: partially-supported
```

`muscle_roles`：`movement.muscle.scapular-upward-rotators`、
`movement.muscle.scapular-elevators`、`movement.muscle.rotator-cuff`。

`name_zh`：流線滑行的肩部避讓機制與肩胛三軸必然性差異

`description` 必須說清楚三件事：

1. **雙重避讓機制**（本筆的骨架）：把手臂舉到頭前最大上舉時，解剖來源描述了
   兩個同時發生、方向不同的讓位動作——**肱骨外旋**（讓肱骨大結節從肩峰後方
   通過）與**肩胛骨後傾**（讓喙肩弓遠離前進中的肱骨頭）。兩者處理的是同一件
   事，一個轉肱骨、一個轉肩胛。所以流線姿勢裡同時標出外旋與後傾**不是重複
   記錄**，是兩個獨立的欄位。
2. **必然性程度不同，這是本筆最重要的內容**：上迴旋與後傾是抬臂過頭的**必然
   伴隨成分**（解剖來源直接把上迴旋定義為抬臂過頭的必要組成，把後傾列為上舉
   過程中的伴隨動作）；**肩胛上提不在必然清單裡**，它是「容許有一些」。
   把三者並列而不區分，會讓讀者以為要同等地「做出」三個動作。
3. **上舉平面會改變外旋需求**：解剖來源指出，在純額狀面上舉與在肩胛骨平面上舉
   的強制外旋耦合程度不同，額狀面的耦合更強。因此「雙臂夾耳但肩胛平面沒有
   跟上」與「整個肩帶沿肩胛平面上舉」是兩個不同的狀況，外旋需求不一樣。
   本層只列出這個差異存在，**不判定哪一種比較好**。

`limitation_context`：上舉角度、上舉平面、肱骨外旋、肩胛上迴旋、後傾與上提
各有獨立的可用範圍與控制條件；從池畔看到的「手臂夾耳伸直」是這些的合成，
**不能指出限制位於哪一個關節或哪一個成分**。另外，外旋的可用範圍本身**隨起始
上舉角度改變**——由手臂貼體側起算與由高上舉位起算不是同一個可用範圍，所以
陸上量到的外旋角度不能直接搬到流線姿勢的判讀上。教材另有「減少迎水面積」
一類說法，該說法屬水動力學，不在本層裁決範圍。

`safety_note`：進入或維持流線姿勢時若出現肩部疼痛、卡住、麻木、明顯無力或
不穩應停止，不要靠外力把手臂往耳側壓，也不要為了把手臂夾得更緊而增加上舉角度。

`movement.muscle.forearm-pronators`、`movement.muscle.forearm-supinators`、
`movement.muscle.wrist-flexors`、`movement.muscle.wrist-extensors`。

`name_zh`：流線滑行的肘腕位置與被手部擺法遮蔽的前臂旋轉

`description` 必須說清楚四件事：

1. **肘伸展是乾淨的命名**：矢狀面單一自由度、無歧義。附帶一點硬體邊界事實：
   正常人的肘可以超過中位再往伸展方向一些，所以「完全伸展」在不同人身上
   對應的實際角度略有差異；教學上不宜用「鎖死」描述，那個詞會誘導停在被動
   結構末端。
2. **腕中立在這裡是合格的用法**：腕的中立有明確的關節定義原點，而且本相位
   只涉及腕的矢狀面屈伸，指涉單一。**但這個合格是有條件的**——若日後要補上
   橈偏尺偏，「中立」就必須分兩軸各自標明。這一句要寫，它是「中立必須綁定
   平面」這條通則的正面範例。
3. **本筆的核心：疊手法遮蔽了前臂旋轉**。掌根相疊、手背相疊、十指交握是三種
   不同的手部擺放方式，它們對應**不同的前臂旋前旋後角度**。教材通常只寫
   「雙手疊合」而完全沒有前臂旋轉欄位，等於用手部的空間關係取代了關節旋轉
   的描述。
4. **而且不能反推**：解剖來源明白指出，手固定時看起來像前臂旋轉的動作，
   本質上可能是盂肱關節的軸向旋轉。所以由手掌朝哪裡去推論前臂在旋前還是
   旋後，在解剖上無效。要判定前臂旋轉必須直接看橈骨相對尺骨的位置。

`limitation_context`：肘伸展、前臂旋轉與腕位置三者獨立；池畔看到的
「手臂伸直、雙手疊好」是三者的合成，不能指出限制在哪一項。
三種疊手法之間的差異在本層只被登錄為「對應不同的前臂旋轉角度」，
**本層不判定哪一種疊手法比較好**——那需要水動力學或運動學證據，本層沒有。
教材另有「延長身體線條」一類說法，該說法屬外觀與水動力學，不在本層裁決範圍。

`safety_note`：疊手或伸直手臂時若出現肘、腕或手部疼痛、卡住、麻木、明顯無力
或不穩應停止，不要為了把手疊得更整齊而強行扭轉前臂或壓迫手腕。

### D4 流線滑行：腰椎基準的雙讀法（本輪唯一的 disputed）

```yaml

    phase: streamlined-glide
    body_position: prone
    poolside_direction: 由池畔觀察，軀幹拉成一直線、腰部既不塌陷也不拱起（教學語常稱「腹部收緊」「空心姿」）
    derived_from_ids:
      - udk.tech.24
    action_ids:
      - movement.action.trunk.flexion
      - movement.action.trunk.extension
    claim_status: disputed
```

`muscle_roles`：`movement.muscle.trunk-sagittal-controllers`。

`name_zh`：流線滑行的腰椎基準——「中立或些微伸展」與「空心姿」指向相反側

**為什麼 `action_ids` 同時列了屈曲與伸展**：這正是本筆要記錄的事。圖譜是
列舉式的——**把可能的狀況都標示出來**，而不是替讀者選一個。教材的同一句話
可以讀成兩個相反方向，本層不裁定哪個對。**不得刪掉其中任何一個，也不得把
其中一個寫成「錯誤說法」。**

`description` 必須說清楚四件事：

1. **矛盾是什麼**：常見寫法是「脊椎維持中立或些微伸展（空心姿）」。但按解剖
   定義，**伸展會加深腰椎前凸**（腰往下沉、腹部前推），而**空心姿依定義是
   腰椎前凸被壓平、下背貼平**，那落在**屈曲側**。兩者不是程度差異，
   是中立點的**兩側**。用括號把它們寫成同義詞，是實質矛盾，不是措辭鬆散。
2. **在流線姿勢裡矛盾會被放大**：解剖來源指出，腰椎伸展**若合併髖關節完全
   伸展**，被拉長的髖屈肌與關節囊韌帶的被動張力會對骨盆產生前傾力，把腰椎
   前凸推得更深。而流線正是下肢完全拉直的姿勢。所以「些微伸展」在這個姿勢下
   不是一個小偏差。
3. **「中立」這半句本身也不合格**：脊椎有三個平面，而且分節段（頸／胸／腰）
   的可用範圍差異顯著。只寫「脊椎維持中立」沒有標節段、沒有標平面，
   既無法驗證也無法教。對照 D3 的髖中立——那一個自帶「不屈不伸」，
   等於綁定了平面與基準，所以合格。
4. **本層的處置**：列出兩個讀法各自指向哪一側，並指出這句話缺的是**節段、
   平面、相對於什麼的基準**三個欄位。要採哪一種寫法屬教學方針決定，
   不由解剖來源裁決，因此本筆 `claim_status` 標 `disputed`——
   **不是說教材錯了，是說現行寫法無論怎麼解讀都內含矛盾，本層不選邊**。

`limitation_context`：本筆不提供「腰椎應該在哪個角度」的答案，也不提供判別
某個泳者現在在屈曲側還是伸展側的方法。凡出現「中立」「些微」「輕度」這類
程度副詞，都必須補齊節段、平面、基準三欄才有意義；本筆記錄的就是這三欄
目前缺失這件事。

`safety_note`：調整腰部姿勢時若出現下背疼痛、放射到腿部的麻木或無力、
或明顯不穩應停止，不要為了做出某一種腰部形狀而強行拱腰或壓平下背。

### D5 上踢期（俯臥）：髖伸展的幅度不對稱

```yaml
  - id: movement.demand.udk.up-kick.hip-extension-prone
    phase: up-kick
    body_position: prone
    poolside_direction: 由池畔觀察，雙腳由最低點朝水面方向移動（教學語稱「上踢」）
    derived_from_ids:
      - udk.tech.10
      - udk.tech.11
      - udk.tech.15
    action_ids:
      - movement.action.hip.extension
      - movement.action.knee.extension
      - movement.action.ankle-foot.plantarflexion
      - movement.action.trunk.extension
    claim_status: partially-supported
```

`muscle_roles`：`movement.muscle.hip-extensors`、`movement.muscle.knee-extensors`、
`movement.muscle.ankle-plantarflexors`。

`name_zh`：俯臥水下海豚腳上踢的髖伸展與可用幅度不對稱

`description` 必須說清楚四件事：

1. **體位與命名的對應**：俯臥時腹側朝池底，所以「腳往水面移動」就是腳往背側
   移動，解剖命名是**髖伸展**。這個命名**只在俯臥時成立**，D6 是仰躺的版本。
2. **髖伸展的可用範圍明顯小於髖屈曲**，而且**膝屈曲時會進一步壓縮**——
   因為跨過髖與膝兩個關節的股直肌被拉長，被動張力把髖伸展的可用量壓回到接近
   中位。這是本筆最實質的內容：**俯臥上踢用的是髖的窄邊**。
3. **因此池畔看到的「腿往上抬」有一部分不是來自髖**：在髖伸展可用量有限的
   情況下，外觀上的腿部上抬會有相當比例來自腰椎伸展與骨盆前傾。所以
   `action_ids` 裡列了軀幹伸展——它不是額外的技術要求，是**幅度歸屬的
   拆帳項目**。
4. **膝與踝的命名不隨體位翻轉**：膝只有屈曲一個方向可用，踝的蹠屈同理，
   所以它們在俯臥與仰躺下是同一個解剖動作名，變的只是它們對應的池畔可見
   方向。**唯有髖與軀幹會發生命名翻轉**，因為只有它們在中立位的兩側都有
   可用範圍。這一句必須寫，否則讀者會把整段打腿描述全部鏡像。

`limitation_context`：髖伸展、膝伸展、踝蹠屈與軀幹伸展各有獨立的可用範圍；
池畔看到的「上踢幅度不足」**不能指出限制位於哪一項**。教材另有把上踢與推進
效益連起來的說法，那些出自游泳運動學與流體量測，不在本層的來源範圍，本筆
不描述、不引用、也不反駁。另外，池畔看到的膝彎曲程度有一個以上的可能來源
（踝的可用蹠屈範圍、髖的位置、主動控制），**外觀本身不能指定是哪一個**。

`safety_note`：上踢時若出現下背、髖前側、膝或小腿疼痛、抽筋、麻木、明顯
無力或不穩應停止，不要靠加大腰部拱起來換取更大的上踢幅度。

### D6 上踢期（仰躺）：同一個可見動作，相反的解剖命名

```yaml
  - id: movement.demand.udk.up-kick.hip-flexion-supine
    phase: up-kick
    body_position: supine
    poolside_direction: 由池畔觀察，雙腳由最低點朝水面方向移動（教學語同樣稱「上踢」，池畔外觀與俯臥時相同）
    derived_from_ids:
      - udk.tech.10
      - udk.tech.11
    action_ids:
      - movement.action.hip.flexion
      - movement.action.knee.extension
      - movement.action.ankle-foot.plantarflexion
    claim_status: partially-supported
```

`muscle_roles`：`movement.muscle.hip-flexors`、`movement.muscle.knee-extensors`、
`movement.muscle.ankle-plantarflexors`。

`name_zh`：仰躺水下海豚腳上踢——同一個池畔動作對應的是髖屈曲

**這是本輪最重要的一筆記錄，寫的時候要意識到它在對抗一句流傳很廣的教材語句。**

`description` 必須說清楚五件事：

1. **這個情境每天都在發生**：仰式選手每一次轉身後都在仰躺體位做水下海豚腳。
   它不是理論上的邊緣案例。
2. **命名為什麼相反**：仰躺時腹側朝水面，所以「腳往水面移動」是腳往**腹側**
   移動，解剖命名是**髖屈曲**——與俯臥版本（D5，髖伸展）完全相反。
   骨動學命名一律從解剖位置起算，**不隨身體在空間中的朝向改變**，
   所以這不是兩種說法，是同一套規則在兩個體位下的兩個結果。
3. **教材常見寫法「動作模式與蝶式的海豚打腿相同」在這裡會出錯**：蝶式是俯臥，
   照抄過來等於把俯臥的命名輸出到仰躺。**要寫成正確的內容，必須先填體位欄位，
   不能用「同蝶式」帶過。** 這句要寫進敘述，它是本筆存在的理由。
4. **力學條件也不對稱，不只是命名鏡像**：髖屈曲的可用範圍**遠大於**髖伸展。
   所以俯臥上踢用的是髖的窄邊、仰躺上踢用的是髖的寬邊。同一句「上踢幅度
   不足」，在兩種體位下**要看的地方不一樣**——本層只列出這個不對稱存在，
   不提供判別流程。
5. **膝與踝不翻轉**：同 D5 第 4 點，照樣寫一次。膝只有屈曲方向可用、踝的蹠屈
   同理，兩種體位下解剖命名不變。

`limitation_context`：髖屈曲、膝伸展與踝蹠屈各自獨立；池畔看到的上踢外觀
在兩種體位下**看起來一樣但解剖內容不同**，所以任何以池畔外觀建立的判讀，
若沒有先記錄體位，就無法對應到關節。本筆不提供任何幅度目標或角度門檻。

`safety_note`：仰躺姿勢下上踢時若出現髖前側、下背、膝或小腿疼痛、抽筋、
麻木、明顯無力或不穩應停止，不要為了加大幅度而讓腰部反折。

## 收尾（六條硬規則，逐條檢查後才算完成）

1. **只 append，不改既有記錄。** 三個檔的既有內容一個字都不動。
2. **釘死欄位逐字照抄**：`stroke: udk`、`phase_model: descriptive`、
   `action_reference_frame: joint-local`、`publication_status: published`、
   `evidence_profile: anatomy`、`action_status: provisional`、
   `source_ids: [src.neumann-2017]`。`body_position` 逐筆照本檔指定
   （D1–D5 是 `prone`，**D6 是 `supine`**）。
3. **敘述裡不得出現 `°`、`%`、`s`、`r=`**（W019 會擋），角度一律改定性說法。
4. **`public` 底下只放 `name_zh`／`description`／`limitation_context`／
   `safety_note`**；任何判讀語、分型、探問句只能放 `diagnostic`（E010 是 ERROR 級）。
5. **D4 的兩個相反 action 與 D6 的髖屈曲不得被「修正」掉。** 這兩處是本輪的
   核心內容，把它們改成單一方向或改成「教材寫錯了」就是任務失敗。
6. **最後跑 `python tools/validate.py`**，必須 0 ERROR，且 W013–W019 全部為 0。
   有非零就自己修到 0 再回報，不要把未通過的結果交出來。
