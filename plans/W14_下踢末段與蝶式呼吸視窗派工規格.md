## 這一層在做什麼（寫任何一個字之前先讀完）

動作圖譜是**列舉式**的：列出「這個相位牽涉到什麼關節動作、可能有哪些狀況」，
**不判定誰主導、不判定某個泳者被什麼限制、不規定要練到幾度、不裁決哪一種教法較好**。

本輪兩筆有一個共同的難處：**它們的素材主體是流體力學與時序，不是關節動作。**
D1 的素材核心是渦流噴射機制，D2 的素材核心是五個時間節點。
**可對到關節的部分很少，而且大多是「避免」而不是「產生」。
這個結構本身就是本輪最值得寫的內容——不要因為「聽起來沒東西」
就去補動作把記錄撐厚。**

### 來源誠實性（本輪特別重要，兩筆都必寫）

本輪素材的來源狀況比前幾批差，**必須在 `assessment_note` 誠實寫出來**：

| 素材記錄 | 它的 `source_ids` | 狀態 |
|---|---|---|
| `udk.tech.6` | `src.university-of-tsukuba-2024-journal-of-biomec-2024` | **unverified，且註冊表裡沒有任何識別碼**（無 DOI／PMID／URL） |
| `udk.tech.9` | `src.researchgate-kinematic-differences`、`src.the-race-club` | **兩個都 unverified**，前者無識別碼，後者只有一個網頁連結 |
| `fly.tech.17` | `src.french-cfd-simulation-undated` | **unverified，無識別碼，連年份都未指定** |
| `fly.tech.16`、`fly.tech.18` | 無 | 確定性標記是推導 |

因此本輪兩筆的 `source_ids` **只掛已查證的解剖來源 `src.neumann-2017`**——
它支持的是**關節命名**，不支持任何游泳相位、時序或推進主張。
**兩筆都要寫明：本筆的關節命名有解剖來源，相位現象本身的來源未經查證，
所以本層只做命名與列舉，不承載素材裡的力學結論。**

以下句型一律不得出現：

- 「下踢末段應外旋 X」「呼吸應在 X 秒內完成」——**這是門檻**
- 「聚攏腳尖能產生推進」「向前不向上比較快」——**這是裁決與速度歸屬**
- 「主要由 X 肌群驅動」——沒有相位化肌電振幅資料
- 「先練 X 再練 Y」——**這是處方**
- 「頸椎後仰會使髖部下沉、阻力激增」——**力學後果本輪一律不寫**

### 兩欄鐵律

**池畔可見方向**與**解剖學動作**是兩個欄位。
`poolside_direction` 寫池畔看到什麼、教練會說出口的那句話；
`action_ids` 與敘述寫解剖學怎麼命名。
**兩欄不一致而未在敘述中標明，一律退件**；不一致處**不得只寫解剖名而不寫
池畔說法**——讀者要能從自己聽過的那句話找到這條記錄。

三種型的定義（沿用 W10–W13）：
**型甲**＝池畔方向與解剖命名相反或錯位；
**型乙**＝池畔說的根本不是一個關節動作（是時序、空間量、力學量）；
**型丙**＝是關節動作，但記錄的是「維持」或「不做」而非「產生」。

本輪的兩欄不一致有七處，**全部必寫**：

| 處 | 池畔／教材說法 | 解剖上是什麼 | 型 |
|---|---|---|---|
| D1 | 「兩隻腳往中間靠、腳尖聚攏」 | 素材歸給**髖外旋**；**庫內沒有髖內收這個動作**，聚攏的內收成分無詞彙可承載 | **甲** |
| D1 | 「踢完會甩出一團水」（渦流叢／噴流） | **流體力學結果**，不是關節動作 | 乙 |
| D1 | 「髖啟動→膝踢出→末段聚攏」 | **時序**，`joint-local` 無欄位承載 | 乙 |
| D2 | 「下巴往前推出去」 | **空間位移**；下巴的位置推不出頸椎角度 | 乙 |
| D2 | 「不要抬頭」 | 頸椎伸展的**避免**，列了 id 是記錄要避開它 | 丙 |
| D2 | 「吸完馬上把頭放回去」 | 頸椎屈曲方向的**回復**，不是產生新的屈曲 | 丙 |
| D2 | 「出水到移臂之間那個空檔吸氣」 | **時序**，是本相位的主體，關節層接不住 | 乙 |

### D1 下踢末段 — 「雙腳聚攏」撞上一個詞彙缺口

```yaml
  - id: movement.demand.udk.terminal-down-kick.hip-external-rotation-and-missing-adduction-term
    stroke: udk
    phase: terminal-down-kick
    phase_model: descriptive
    poolside_direction: 由池畔或水下窗觀察，海豚踢往下打到接近最低點時，兩隻腳往中間靠、腳尖幾乎併在一起，膝蓋這時已經打直（教學語稱「腳尖夾起來」「最後把水擠出去」）
    derived_from_ids:
      - udk.tech.6
      - udk.tech.9
    action_ids:
      - movement.action.hip.external-rotation
      - movement.action.knee.extension
```

`muscle_roles`：`movement.muscle.hip-external-rotators`、
`movement.muscle.knee-extensors`。

`name_zh`：下踢末段的髖外旋與膝伸展，以及「雙腳聚攏」缺少的動作詞

`description` 必須依序寫齊六件事：

1. **「兩隻腳往中間靠」在素材裡被歸給髖外旋，這與直覺相反（型甲，本筆核心之一）**。
   池畔看到兩腳往身體中線靠攏，直覺會把它叫成「內收」「夾腿」。
   素材描述的是**髖關節的外旋**——大腿繞自身長軸向外轉時，
   小腿與足會被帶到相對靠內的位置，**看起來像夾，實際上是轉**。
   要寫明：**池畔的「靠攏」是足部在空間中的位置變化，
   髖外旋是大腿繞長軸的旋轉，兩者不是同一個量**；
   由足部位置反推不出髖旋轉了多少。

2. **「聚攏」的內收成分在庫內沒有動作詞可以承載（詞彙缺口，必寫）**。
   要寫明：足部靠攏這個可見現象，除了髖外旋之外還可能包含髖的內收成分，
   但**本專案的動作詞彙表沒有登錄髖內收這個動作**，因此這個成分
   **在這一層無法被列舉**。
   還要寫明：**`action_ids` 刻意不列髖外展來反向表示這件事**——
   列了外展會被讀成「這個相位要做外展」，意思正好相反。
   ⚠ 這是**詞彙表的缺口**，不是這一筆的疏漏，要如實記錄，
   **但不得在敘述裡要求補這個詞**（那是 taxonomy 的決策，不在本層）。

3. **膝伸展在池畔與解剖命名一致**。下踢末段膝已伸直，對到
   `movement.action.knee.extension`，不需要轉譯。
   要寫明：**下踢前段的膝屈曲屬於下踢相位本身，庫內已有記錄，本筆不重述**；
   **踝蹠屈同樣已由下踢相位那一筆承載**，所以 `action_ids`
   **刻意不列踝蹠屈**——不是這個相位沒有踝的參與，
   而是它的通則已經記錄在別處，重複列會讓兩筆內容互相覆蓋。
   這句要正面寫出來，否則讀者會以為漏了腳踝。

4. **「踢完甩出一團水」是流體力學結果，不是關節動作（型乙）**。
   素材用可視化方法描述下踢末段周圍的水流結構。要寫明：
   **水流結構是關節動作在水裡造成的結果，不是一個可以被命名、被指令的關節動作**；
   本層不承載它。
   ⚠ **不得寫渦流強度、不得寫推進力、不得寫「游得越快渦流越強」
   之類的速度關係。**

5. **「髖啟動→膝踢出→末段聚攏」是時序（型乙）**。
   素材把下踢描述成一個有先後的序列。要寫明：
   **這個序列描述的是幾個事件在時間上的相對位置，
   在 `joint-local` 框架下沒有任何一個關節動作能承載它**；
   而且**序列開頭的髖屈曲屬於下踢相位，庫內已有記錄，本筆不重述**。
   ⚠ **不得寫誰先誰後可以訓練、不得寫最優膝屈曲角度**（是門檻，且是數字）。

6. **來源狀態必須誠實**（見上方通則），這句寫進 `assessment_note` 即可，
   不必在 `description` 重複。

`limitation_context`：髖外旋與膝伸展是兩個獨立成分，足部在空間中的靠攏程度
是第三個**不屬於關節層**的觀察值，而它的內收成分**在本專案的動作詞彙表裡
沒有對應項目**；池畔看到的「腳尖夾得很好」是這些的合成，
**不能指出限制位於哪一個關節，也不能由腳尖位置判定髖外旋是否到位。**
渦流結構、推進力、踢腿速度與出水銜接都不在本筆。

`safety_note`：做下踢末段的腿部轉動與伸展時若出現髖部、鼠蹊、膝部、腰背或踝部
疼痛、麻木、明顯無力或不穩應停止，不要為了把腳尖夾得更緊
而強行轉動大腿或把膝蓋鎖到底。

`diagnostic.assessment_note`：要推進這一筆，缺的是**下踢末段的三維髖旋轉與
足部空間位置的同步量測**——只有分開量到這兩者，才能判斷可見的「聚攏」
有多少來自髖外旋、有多少來自其他成分。
再寫來源狀態：**兩筆素材記錄所掛的來源在來源註冊表裡都是未查證狀態，
其中兩個連識別碼都沒有登錄**，所以本筆的 `source_ids` 只掛已查證的解剖來源，
它支持的是關節命名，不支持素材裡的渦流與推進結論。
再寫詞彙缺口：**髖內收未登錄於動作詞彙表，是這一筆無法完整列舉的直接原因**，
這是 taxonomy 層的待決事項，記錄在此不代表本層有權補。
收尾寫 `action_status: provisional` 的理由。

`description` 必須依序寫齊五件事：

1. **「呼吸視窗」不是划手週期切出來的一段（本筆核心，必須寫在最前面）**。
   登錄表裡其他相位都是把一個週期切成連續的段落；
   **呼吸視窗是全登錄表唯一使用「事件視窗」這個分期模型的相位**——

   而不是每個週期都必然經過的一段動作。
   要寫明：因此本筆列出的動作**不是「這個相位要做的動作」，
   而是「這個視窗被使用時，頸椎會發生什麼」**。

2. **「下巴往前推出去」是空間位移，不是關節動作（型乙）**。
   要寫明：下巴在空間中的位置是頸椎角度、胸椎角度與整個身體在波動中的
   姿態三者的合成，**單看下巴推到哪裡，推不出頸椎伸展了多少**。
   因此 `action_ids` **沒有、也不可能有**一個叫「向前」的動作——
   **關節動作詞彙描述的是體節相對體節的角度變化，不是體節在空間中的位移。**

   素材描述的正確做法是不把頸椎仰起來。
   ⚠ **不得寫「仰起來會怎樣」的後果**（力學後果與速度歸屬本輪不寫），

   要寫明：這是**回到視窗開啟前已有的位置**，不是在這個視窗裡產生一個新的屈曲。
   還要寫明：**同一個關節區域的兩個相反動作同時出現在 `action_ids` 裡，
   一個是避免、一個是回復**——這不是矛盾，是這個視窗的實際結構。

5. **本相位的主體是時序，而關節層接不住（必寫）**。
   素材把呼吸描述成一串時間節點：手臂在水下時頭埋著、手臂推到後段時

   ⚠ **不得寫節點的先後可以訓練、不得寫呼吸時間長短、不得寫換氣頻率
