## ⚠ 本檔最重要的一件事：兩個分期模型同時存在，不得互相換算

自由式在登錄表裡**同時有三個分期模型**，本輪橫跨其中兩個：

| 模型 | 本輪的相位 |
|---|---|
| `race-club-6phase`（六階段划手週期） | D1 升力相、D2 後象限推進、D4 釋放相、D5 早期回臂、D6 晚期回臂 |
| `kudo-power-phase`（動力相位） | D3 推水相 |

**D2（後象限推進）與 D3（推水相）在時間上重疊，但它們是兩個模型的兩個相位，
邊界定義不同，不得互相換算，也不得互相搬運數值。**

這條在庫內已經有兩個先例：
`movement.demand.free.front-quadrant-propulsion.wrist-isometric-stability`
明寫「兩者使用的分期不同，內掃相不能換算成六相模型的前象限推進期」；
登錄表 `free.early-pull-through` 的 `note` 也明寫三個相位「界線定義各不相同，
不得互相換算」。

**具體禁令（違反即退件）**：

1. **D2 不得出現任何百分比**。素材記錄 `free.tech.16` 裡的
   「推水相約為 32%、37%、31%」是 **kudo 推水相**的量測，
   **不是 race-club 後象限推進的量測**。把它寫進 D2 就是跨模型換算。
2. **D3 不得轉錄拉水相的數值**（`free.tech.16` 裡另有一組拉水相的貢獻比例）。
   拉水相屬 `movement.demand.free.pull.upper-trunk-rotation-hand-velocity`，
   **那一筆已存在**，D3 只寫推水相。
3. **D2 與 D3 各自都要寫一句**：另一個模型有一個時間上重疊的相位，
   兩者邊界定義不同、不可換算。**只指路，不重述對方內容。**

## 這一層在做什麼（寫任何一個字之前先讀完）

動作圖譜是**列舉式**的：列出「這個相位牽涉到什麼關節動作、可能有哪些狀況」，
**不判定誰主導、不判定某個泳者被什麼限制、不規定要練到幾度、不裁決哪一種教法較好**。

本輪素材有一個貫穿全批的性質：**`free.tech.8`、`free.tech.4`、`free.tech.5`、
`free.tech.29`、`free.tech.32` 五筆全部沒有 `source_ids`，確定性是 🟠（教練觀測）。**
它們是 Race Club 教材體系的相位模型，不是量測研究。
因此本輪五筆（D1、D2、D4、D5、D6）的關節內容**只靠解剖學命名成立**，
相位現象本身沒有文獻登錄。**這件事要誠實寫進每一筆的 `assessment_note`，
不得含糊帶過，也不得因此就把記錄寫得像有研究支撐。**

以下句型一律不得出現：

- 「升力相應維持 X」「回臂肘部應彎曲 X 度」——**這是門檻**
- 「推到底比較快」「直臂回臂適合衝刺」——**這是裁決與速度歸屬**
- 「主要由背闊肌驅動」「X 是後象限的主動肌」——沒有相位化肌電振幅資料
- 「先練 X 再練 Y」「找出限制你的那塊肌肉」——**這是處方**
- 「肘部下沉會讓推進力歸零」——**力學後果與速度歸屬本輪一律不寫**

### 兩欄鐵律

**池畔可見方向**與**解剖學動作**是兩個欄位。
`poolside_direction` 寫池畔看到什麼、教練會說出口的那句話；
`action_ids` 與敘述寫解剖學怎麼命名。
**兩欄不一致而未在敘述中標明，一律退件**；不一致處**不得只寫解剖名而不寫
池畔說法**——讀者要能從自己聽過的那句話找到這條記錄。

三種型的定義（沿用 W10–W12）：
**型甲**＝池畔方向與解剖命名相反或錯位；
**型乙**＝池畔說的根本不是一個關節動作（是時序、空間量、力學量）；
**型丙**＝是關節動作，但記錄的是「維持」或「不做」而非「產生」。

本輪的兩欄不一致有十三處，**全部必寫**：

| 處 | 池畔／教材說法 | 解剖上是什麼 | 型 |
|---|---|---|---|
| D1 | 「手走到三點鐘位置」 | 時鐘位置是**手相對靜水的空間位移**，不是任何關節的角度 | 乙 |
| D1 | 「入水後先往前送、不要急著壓」 | 肩上舉的**維持**＋肘伸展的**維持**＋下壓的**延後** | 丙 |
| D1 | 「這一派入水就抓水，那一派先延伸」 | 同一組動作的**時間差**，不是方向差；`action_ids` 無欄位承載時間 | 乙 |
| D1 | 「延伸是把肩膀送出去」 | 軀幹繞長軸旋轉（`trunk.axial-rotation`），不是肩自己往前 | 甲 |
| D1 | 「手掌轉向後方準備抓水」 | 掌心朝向**推不出**任何關節動作 | 乙 |
| D2 | 「手走到九點鐘、推到底」 | 同上，時鐘位置是空間位移 | 乙 |
| D2 | 「推進力在這裡最大」 | 力學量，**且本層不裁定誰主導** | 乙 |
| D2 | 「出手時髖部往後甩」（hip-snap） | 解剖歸屬是**軀幹繞長軸旋轉**，**不是髖伸展** | **甲** |
| D4 | 「小指先出水」 | 小指／掌心的空間朝向**推不出**肩旋轉或前臂旋轉 | **乙／禁止項** |
| D5 | 「手腕放鬆」 | 腕**中立**＝屈與伸兩個動作**都不做** | 丙 |
| D5 | 「彎臂回臂／直臂回臂」 | 是肘屈曲**程度的連續光譜**，本層列舉光譜存在，**不裁定該用哪一層** | 乙 |
| D6 | 「靠重力把手砸下去」 | 重力是**外力**，不是關節動作 | 乙 |
| D6 | 「手砸得越用力、身體轉得越快」 | 同一個連動的**兩個觀察面**，不是兩個可分別下令的關節動作 | 乙 |

### 軀幹旋轉不掛肌群（強制，不得例外）

庫內既有記錄 `movement.demand.free.pull.upper-trunk-rotation-hand-velocity`
的 `muscle_roles` **刻意留空**，理由寫在它的 `assessment_note`：軀幹肌群的肌電與
軀幹扭轉之間有數百毫秒級延遲，其角色被解讀為姿勢與穩定控制，不是產生扭轉的驅動端；
掛上「軀幹旋轉肌群」等於把體節間共變寫成近端驅動遠端。

**本輪 D1、D2、D3 都列了 `movement.action.trunk.axial-rotation`，
三筆的 `muscle_roles` 一律不得為它掛任何肌群**，並在各自的
`assessment_note` 寫明沿用這個理由（一句話即可，不必重寫論證）。
庫內也**沒有**軀幹旋轉肌群這個 id，硬掛會被 W014 擋下。

### D1 升力相 — 風格差異在這裡是時間差，不是方向差

```yaml
  - id: movement.demand.free.lift.deferred-descent-and-style-time-difference
    phase: lift
    phase_model: race-club-6phase
    poolside_direction: 由池畔觀察，手入水之後在身體前方由淺處往前下方移動，準備開始抓水；不同泳者在這一段的做法明顯不同——有人入水後立刻把手往下壓，有人先把手往前送一段才開始下壓（教學語稱「先延伸再抓水」「入水就要抓」）
    derived_from_ids:
      - free.tech.8
      - free.tech.4
      - free.tech.5
    action_ids:
      - movement.action.shoulder-complex.elevation
      - movement.action.elbow.extension
      - movement.action.trunk.axial-rotation
```

`muscle_roles`：`movement.muscle.scapular-upward-rotators`、
`movement.muscle.rotator-cuff`、`movement.muscle.elbow-extensors`。
**`trunk.axial-rotation` 不掛肌群。**

`name_zh`：升力相的上舉維持與下壓延後，以及風格差異的時間性質

`description` 必須依序寫齊五件事：

1. **本相位的關節內容主體是「維持」與「延後」，不是「產生」**。
   手入水後在前方的位置由**肩複合體維持在上舉位**與**肘維持伸展**構成，
   兩者在入水瞬間就已達成，升力相只是不去破壞它們。
   要寫明這是維持，不是這個相位新產生的動作。

2. **「手走到三點鐘位置」是空間位移，不是關節角度（型乙）**。
   教材用一個時鐘模型描述手的軌跡，並且明說這個時鐘的直徑只有大約兩個手掌臂長
   的尺度——因為手在水下移動的同時身體也在前進，**時鐘標的是手相對靜水的位移，
   不是手相對身體的角度**。要寫明：時鐘位置**不能反推任何一個關節的角度**，
   同一個時鐘位置可以由不同的肩、肘、軀幹組合達成。
   ⚠ **時鐘的數字（幾點鐘）與那個長度都不得寫進敘述**，只描述性質。

3. **「入水就抓」與「先延伸再抓」是同一組動作的時間差（型乙，本筆核心）**。
   兩種做法在關節層列出的動作**完全相同**，差別只在下壓開始的**時間點**。
   要寫明：**`action_ids` 沒有任何欄位可以表達「什麼時候開始」，
   所以這個差異只能靠敘述說清楚；讀者不能從 id 列表本身讀出兩種風格的存在。**
   ⚠ **不得裁決哪一種風格較好、適合什麼距離、划頻多少**——
   那是教學決策，且素材裡的划頻數字一律不轉錄。

4. **「延伸是把肩膀送出去」的解剖歸屬是軀幹旋轉（型甲）**。
   池畔說「手再往前送一點」，看起來像是手臂自己往前伸長。
   解剖上，這一段可及範圍的增加主要來自**軀幹繞長軸的旋轉把該側肩帶送向前方**
   （`movement.action.trunk.axial-rotation`），不是肩關節產生了額外的前伸角度。
   要寫明兩者不是同一件事。
   ⚠ **不得寫轉多少度、不得寫轉體幅度與划距的關係**——
   庫內既有記錄已明寫「滾轉可以增加划距」目前沒有對應量測。

5. **「掌心轉向後方準備抓水」不能反推關節旋轉（型乙）**。
   掌心的空間朝向是肱骨軸向旋轉、前臂旋前旋後與腕位置三者的合成，
   單看朝向分辨不出來自哪一個。因此 `action_ids` **刻意不列**
   `shoulder-complex.internal-rotation` 與 `forearm.pronation`。
   這句要正面寫出來，否則讀者會以為是漏了。
   完整論證屬 `movement.demand.free.catch.palm-orientation-three-source-decomposition`，
   **本筆只寫一句指路，不重述、不改寫、不節錄。**

6. **參考系混用一句**（見上方通則）。

`limitation_context`：肩上舉維持、肘伸展維持與軀幹旋轉是三個獨立成分，
「下壓的開始時間」是第四個**時間**維度；池畔看到的「延伸得很好」是它們的合成，
**不能指出限制位於哪一個關節，也不能由前伸的外觀判定任何一個成分已經到位。**
划頻、風格歸類、抓水品質與推進力都不在本筆。

`safety_note`：維持手臂前伸上舉位與軀幹轉動時若出現肩部、頸部、背部或腰部疼痛、
麻木、上肢放射症狀、明顯無力或不穩應停止，不要為了把手送得更遠
而強行增加上舉角度或加大軀幹扭轉。

`diagnostic.assessment_note`：要推進這一筆，缺的是**升力相的三維肩、肘與軀幹
角度量測，以及下壓開始時間的量測**。現有素材是 Race Club 的相位模型與風格分類，
**三筆素材記錄（`free.tech.8`、`free.tech.4`、`free.tech.5`）的 `source_ids`

再寫：`trunk.axial-rotation` 不掛肌群的理由（沿用 `free.pull` 那一筆）、
