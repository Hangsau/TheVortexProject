### 1.2 為什麼現在看起來亂

1. **42 篇排成一整串，沒有分組。** 頁面沒設 `weight`，Hugo 改用日期和標題排，五個主題混在一起，心理 01–08 的順序也被打散。
2. **卡片摘要是內部頁首，不是內容。** 像「建立日期：2026-04-17」「dossier 性質：原始彙整，非最終稿」「定位：前一篇……」這類字樣。讀者從卡片看不出這篇在講什麼。
3. **清單頁說明漏了最大的一類。** 說明只寫「心理、感知科學、物理現象、週期化」，沒寫比賽成績分析（15 篇）。
4. **兩種性質的東西混在一起。** 文獻整理是「別人研究過什麼」，比賽分析是「我們自己算出來什麼」。兩者證據性質和讀法都不一樣，現在卻沒有區分。
5. **只有心理有總覽。** 其他主題沒有入口頁，也沒有閱讀順序。比賽分析 15 篇彼此「接續前一篇」，但沒有一張地圖說明先讀哪篇。
6. **筆記和知識點沒有接起來。** 看不出哪個結論已經寫進知識點、哪個還停在研究中。
7. **名單寫死在 my-site。** 要公開哪幾篇、網址叫什麼，寫在 `my-site/tools/sync_vortex.py` 的 `NOTE_SLUGS`，Vortex 這邊沒有登錄表，違反「索引由資料生成、單一真相來源」。
8. **規劃文件過期。** `RESEARCH_PLAN.md` 還是 4 月訂的 Layer 0–3 架構，對不上現在實際長出來的五個主題。`FUTURE_RESEARCH.md` 的已畢業、未畢業、4 月的舊想法和 10 月的新問題都混在同一份。

- **位置不變**：放在研究庫，不進知識區。知識區只放 canonical 生成的知識點，研究筆記是「整理成知識點之前的原料」。這是 10-14 三層重構定下的分層，不推翻。
- **要改的是研究筆記區本身**：從一整串清單，改成「分兩大類 → 分主題 → 每個主題有總覽和閱讀順序」。

### 2.2 每張卡片與每篇筆記頂部的固定格式

- **卡片**：標題＋一句「這篇的結論」（讀者看得懂的白話）＋狀態標籤。
- **狀態只用三種**：`研究中`／`已寫進知識點`（附連結）／`已撤回`（保留原文作紀錄）。
- **筆記頂部**：一句話結論、證據性質（自己分析／文獻整理／教學觀察）、狀態。原本的「建立日期／dossier 性質」移到登錄表，不留在公開文字（比照 W029「修訂史不進公開文字」）。

## 3. 機制：研究筆記登錄表

新增 `Research/_notes.yaml`，作為研究筆記的唯一真相來源，取代 my-site 寫死的 `NOTE_SLUGS`：

```yaml
groups:            # 大類與主題，順序即網站順序
  - key: analysis
    name_zh: 我們算出來的
    themes:
      - {key: race-swim, name_zh: 一趟比賽怎麼游完}
      ...
notes:
  - id: note.fade-causes
    path: 競賽成績分析/掉速成因_轉身前加速.md
    slug: fade-causes          # 既有網址不改
    theme: race-swim
    order: 3
    kind: analysis             # analysis | literature | observation
    status: researching        # researching | graduated | retracted
    summary_zh: 前段比平常快 1%，最後 50 會多掉約 0.55 個百分點；短池掉得比長池多。
    graduated_to: []           # canonical 知識點 ID
    open_questions: [fq.0.10]
non_public:                    # 刻意不公開的檔案與理由；不在 notes 也不在這裡 → 驗證失敗
  - {path: 週期化/Olbrecht_游泳能量系統.md, reason: 整本書萃取（著作權）}
```

驗證（加進 `tools/validate.py` 或獨立 `tools/check_notes.py`）：
- `Research/`、`Observations/` 底下每個 `.md` 都必須出現在 `notes` 或 `non_public`（不能有沒歸屬的檔案）。
- slug 不可重複、theme 必須已宣告、`graduated_to` 指向的 canonical ID 必須存在。
- `summary_zh` 不可為空，也不可以「建立日期／dossier／定位：」開頭。

my-site 端：`sync_vortex.py` 改讀 `_notes.yaml`，寫出 front matter 的 `weight`、`theme`、`status`、`description=summary_zh`；清單頁改成依大類和主題分組。
